# Versioning and release

## The `VERSION` file

[`VERSION`](../VERSION) at the repository root contains **only** the application version, in `MAJOR.MINOR.PATCH` form ([SemVer](https://semver.org/)), followed by a newline:

```
0.1.0
```

It is the **only** place the version is written. The backend, the web front, the APK and the GitHub release all read it (see [architecture.md §8](architecture.md#8-versioning-across-components)). Do not copy the version anywhere else. `package.json` versions stay at `0.0.0` and are ignored.

| Bump | When |
|------|------|
| MAJOR | Incompatible change: API breaking change, migration that needs manual steps |
| MINOR | New feature |
| PATCH | Bug fix only |

**Constraint:** MINOR and PATCH must be **≤ 99**, because the Android `versionCode` is computed as `MAJOR × 10000 + MINOR × 100 + PATCH` (`0.1.0` → `100`, `1.2.3` → `10203`). CI rejects versions that break this rule.

## Releasing

1. On a branch: bump `VERSION`, then move the `## [Unreleased]` entries of [`CHANGELOG.md`](../CHANGELOG.md) under a new `## [X.Y.Z] - YYYY-MM-DD` heading.
2. Open a PR. CI must pass.
3. Merge into `main`. The **Release APK** workflow starts because `VERSION` changed.
4. The workflow:
   1. reads and validates `VERSION`, and **stops without error** if the tag `vX.Y.Z` already exists (so a version is only released once);
   2. builds the web bundle and runs `cap sync android`;
   3. runs `gradlew assembleRelease`, aligns the APK with `zipalign` and signs it with `apksigner` using the release keystore;
   4. checks that the APK's `versionName` equals `VERSION`;
   5. creates the tag `vX.Y.Z` and a **GitHub Release** named `Self-Notes vX.Y.Z`. The release notes are the CHANGELOG section for that version (or notes generated by GitHub if there is no section). It attaches `Self-Notes-vX.Y.Z.apk` and its `.sha256`.

The workflow can also be started by hand (**Actions → Release APK → Run workflow**), for example for the very first release or after fixing a failed run. It always releases the `VERSION` currently on the branch.

## Workflows

| File | Trigger | Does |
|------|---------|------|
| [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) | PRs, pushes to `main`, manual | Validates `VERSION` and `docker-compose.yml`. Lint, typecheck, test and build for the backend (against a SQLite file) and the frontend. Runs the native unit tests and builds a debug APK (artifact kept 7 days). Builds the Docker images, starts the stack and runs the end-to-end tests (Playwright). Each module's job is skipped until that module exists. |
| [`.github/workflows/release-apk.yml`](../.github/workflows/release-apk.yml) | Push to `main` that changes `VERSION`, manual | Builds, signs and publishes the release APK (above). Skipped while `frontend/android` does not exist. |

## Android project requirements

`frontend/android/app/build.gradle` reads the version from `VERSION` (path relative to `frontend/android/`). The Gradle build itself fails if `VERSION` is not `MAJOR.MINOR.PATCH` or if MINOR or PATCH is above 99:

```groovy
def appVersion = rootProject.file('../../VERSION').text.trim()
def (vMajor, vMinor, vPatch) = appVersion.tokenize('.').collect { it as int }
// + format and <= 99 checks

android {
    defaultConfig {
        applicationId "app.selfnotes"
        versionName appVersion
        versionCode vMajor * 10000 + vMinor * 100 + vPatch
        // ...
    }
}
```

The release build type has **no** `signingConfig`, because signing is done afterwards by the workflow. So Gradle produces `app/build/outputs/apk/release/app-release-unsigned.apk`, which is the path the workflow expects.

## Signing keystore (one-time setup)

> ⚠️ Keep the keystore and its passwords safe and backed up **outside the repository**. If they are lost, the next APK cannot be installed over the previous one: users would have to uninstall the app first, and lose its local data.

1. Generate the keystore:
   ```bash
   keytool -genkeypair -v -keystore self-notes-release.jks -alias self-notes \
     -keyalg RSA -keysize 4096 -validity 10000
   ```
2. Encode it in base64 for GitHub:
   ```bash
   base64 -w0 self-notes-release.jks > self-notes-release.jks.b64
   ```
3. In **GitHub → Settings → Secrets and variables → Actions**, add:

   | Kind | Name | Value |
   |------|------|-------|
   | Secret | `ANDROID_KEYSTORE_BASE64` | content of `self-notes-release.jks.b64` |
   | Secret | `ANDROID_KEYSTORE_PASSWORD` | keystore password |
   | Secret | `ANDROID_KEY_ALIAS` | `self-notes` |
   | Secret | `ANDROID_KEY_PASSWORD` | key password |
   | Variable (optional) | `DEFAULT_SERVER_URL` | server URL pre-filled on the APK login screen, e.g. `https://notes.example.com` |

4. Delete the `.b64` file. `*.jks` and `*.keystore` are git-ignored.

The workflow fails early with a clear message if any secret is missing.

## Installing the APK

Download `Self-Notes-vX.Y.Z.apk` from the GitHub Releases page on the phone, and allow "install unknown apps" for the browser when Android asks. Newer versions install over older ones as long as they are signed with the same keystore.
